## A. Pré-checagens (SÓ LEITURA) e backup

### A.1. Commit e migration atuais de produção

```bash
cd /var/www/gestfila
git log --oneline -1
git status --short
```
**Esperado:** a 1ª linha mostra o commit atual — **anote como
`<COMMIT_ANTERIOR>`** (necessário para o rollback). `git status --short` sem
saída (nenhum arquivo modificado à mão no servidor). Se houver saída, PARE e
avalie antes de seguir: o `git pull` pode conflitar.

```bash
mysql -u gestfila -p'<SENHA_MYSQL>' gestfila -e "SELECT version_num FROM alembic_version;"
```
**Esperado:** `b3d6f8a1c4e7` (migration do 10.67). Se vier outro valor, PARE:
há migrations anteriores pendentes e este roteiro precisa ser revisto.

### A.2. Backup do banco (antes de qualquer outra coisa)

```bash
sudo mkdir -p /opt/gestfila-backups
ARQ=/opt/gestfila-backups/gestfila_pre_10_69_a_10_74_$(date +%Y%m%d_%H%M).sql.gz
mysqldump -u gestfila -p'<SENHA_MYSQL>' --single-transaction --routines --triggers --no-tablespaces gestfila \
  | gzip | sudo tee "$ARQ" > /dev/null
ls -lh "$ARQ"
gunzip -c "$ARQ" | tail -1
echo "$ARQ"
```
**Esperado:** tamanho compatível com os backups diários (não alguns bytes);
a penúltima saída é `-- Dump completed on <data e hora>` — só aparece num
dump COMPLETO (se o `mysqldump` falhar, por exemplo senha errada, o `gzip`
ainda cria um arquivo válido, por isso a conferência é por esta linha e não
pelo `gunzip -t`). A última saída é o caminho do arquivo: anote como
`<ARQUIVO_BACKUP>`.

> `--no-tablespaces` evita o erro de privilégio `PROCESS` do MySQL 8 para um
> usuário que não é root; `--single-transaction` faz o dump sem travar as
> tabelas (o sistema pode continuar rodando durante o backup).

### A.3. Siglas duplicadas (pré-requisito da migration do 10.71)

SELECT empresa_id, sigla, COUNT(*) AS qtd

### A.4. Siglas atuais e colisões de sigla automática (planejamento do passo C)

```bash
mysql -u gestfila -p'<SENHA_MYSQL>' gestfila -e "
SELECT id, empresa_id, nome, sigla, UPPER(LEFT(nome, 3)) AS sigla_automatica
FROM unidades ORDER BY empresa_id, sigla_automatica, nome;"
```
**Esperado:** a lista de unidades. Onde `sigla` é NULL, vale a
`sigla_automatica`. Unidades da mesma empresa com a MESMA sigla automática
(ex.: as duas "Anápolis - ..." → `ANÁ`) são as que precisam de sigla no
passo C — anote as siglas que vai cadastrar (2 a 4 letras A-Z/dígitos, sem
acento).

### A.5. Filas com nome repetido (10.69)

```bash
mysql -u gestfila -p'<SENHA_MYSQL>' gestfila -e "
-- (a) mesmo nome em UNIDADES diferentes: resolvido pelo prefixo [SIGLA]
SELECT f.empresa_id, MIN(f.nome) AS nome, COUNT(DISTINCT f.unidade_id) AS unidades,
       GROUP_CONCAT(CONCAT(f.id, ':', u.nome, IF(f.ativo, '', ' (inativa)')) SEPARATOR ' | ') AS filas
FROM filas f JOIN unidades u ON u.id = f.unidade_id
GROUP BY f.empresa_id, f.nome HAVING COUNT(DISTINCT f.unidade_id) > 1;

-- (b) mesmo nome DENTRO da mesma unidade: o prefixo NÃO resolve
SELECT f.empresa_id, u.nome AS unidade, MIN(f.nome) AS nome, COUNT(*) AS qtd,
       GROUP_CONCAT(CONCAT(f.id, IF(f.ativo, '', ' (inativa)')) ORDER BY f.id) AS ids
FROM filas f JOIN unidades u ON u.id = f.unidade_id
GROUP BY f.empresa_id, f.unidade_id, f.nome HAVING COUNT(*) > 1;"
```
**Esperado:** (a) pode ter várias linhas — normal, é o caso que a leva
resolve com "[SIGLA] Nome". (b) idealmente vazio. Cada linha de (b) vai
aparecer nas telas como "[SIGLA] Nome (id)" em TODOS os membros do grupo
(regra do 10.32/10.69) — trate como dado (renomear ou desativar a fila
duplicada), quando quiser; não bloqueia o deploy. A comparação é a da
collation do banco (ignora maiúsculas e acentos).

### A.6. Volume de senhas por dia (calibrar o relatório "Tempos por senha", 10.73)

```bash
mysql -u gestfila -p'<SENHA_MYSQL>' gestfila -e "
-- Dia civil de Brasília (UTC-3, sem horário de verão desde 2019)
SELECT DATE(DATE_SUB(criada_em, INTERVAL 3 HOUR)) AS dia, COUNT(*) AS senhas
FROM senhas GROUP BY dia ORDER BY senhas DESC LIMIT 10;

SELECT DATE(DATE_SUB(s.criada_em, INTERVAL 3 HOUR)) AS dia, u.nome AS unidade, COUNT(*) AS senhas
FROM senhas s JOIN unidades u ON u.id = s.unidade_id
GROUP BY dia, u.nome ORDER BY senhas DESC LIMIT 10;

-- Últimos 30 dias, por unidade (tamanho de um filtro mensal)
SELECT u.nome AS unidade, COUNT(*) AS senhas_30_dias
FROM senhas s JOIN unidades u ON u.id = s.unidade_id
WHERE s.criada_em >= UTC_TIMESTAMP() - INTERVAL 30 DAY
GROUP BY u.nome ORDER BY senhas_30_dias DESC;"
```
**Esperado:** só números para decisão — não bloqueia o deploy. Envie o
resultado para calibrar `LIMITE_LINHAS_PDF` (hoje 500) e
`LINHAS_POR_PAGINA` (hoje 100) em `app/relatorios/routes.py`.

### A.7. Locais com o prefixo automático das unidades que vão ganhar sigla

### B.5. Migration

```bash

```
**Esperado:**
- 1º `current`: `b3d6f8a1c4e7`
- `upgrade`: `Running upgrade b3d6f8a1c4e7 -> c7e2a9d4f1b3, Unicidade de unidades.sigla por empresa (adendo 10.71)`

## C. Pós-deploy: cadastrar as siglas (tela de Unidades)

Faça com um usuário admin (ou super admin), **nesta ordem**:

1. **Admin → Unidades.** A coluna "Sigla" mostra a sigla efetiva; as
   automáticas aparecem como "ANÁ (automática)" e as que colidem com o aviso
   "igual à de ... - cadastre uma sigla".
2. **Primeira Anápolis:** Editar "Anápolis - Centro Médico" → campo "Sigla" →
   `<SIGLA_ANAPOLIS_1>` (ex.: `ACM`) → Salvar.
   - Se ela tiver locais com o prefixo `[ANÁ]`, abre a **prévia "Atualizar
     prefixo dos locais"** (antes → depois). Confira a coluna da direita: se
     algum item mostrar "já usado pelo local ...", ajuste esse local à mão
     antes. Sem colisões, clique **"Atualizar locais"**.
   - "Agora não" também é seguro: a sigla fica salva, e a listagem passa a
     avisar "N locais ainda usam o prefixo [ANÁ]" com um link para refazer a
     prévia depois.
3. **Segunda Anápolis:** o mesmo para "Anápolis - Laboratório" com
   `<SIGLA_ANAPOLIS_2>` (ex.: `ALB`).
   - A tela recusa uma sigla igual à automática de outra unidade, ignorando
     acento (ex.: "ANA" enquanto a outra ainda é "ANÁ") — por isso a ordem.
4. **Demais unidades (opcional):** cadastrar a própria sigla automática
   ("MAT" na Matriz, "LAR" na Laranjeiras etc.) não muda nada na tela nem nos
   locais — só deixa a sigla explícita.
5. Voltar à listagem: nenhum aviso "igual à de ..." e nenhum "locais ainda
   usam o prefixo" (salvo os que você escolheu deixar para depois).

## E. Rollback

Use se algo crítico quebrar e não houver correção rápida.

> **Ordem importa:** o downgrade da migration precisa rodar ANTES de voltar o
> código — o arquivo da migration `c7e2a9d4f1b3` só existe no código novo.

### E.1. Desfazer a migration (com o código NOVO ainda no servidor)

```bash
cd /var/www/gestfila
source venv/bin/activate
flask db downgrade b3d6f8a1c4e7
flask db current
mysql -u gestfila -p'<SENHA_MYSQL>' gestfila -e "SHOW INDEX FROM unidades;"
```
**Esperado:** `Running downgrade c7e2a9d4f1b3 -> b3d6f8a1c4e7`; `current` =
`b3d6f8a1c4e7`; `SHOW INDEX` com `PRIMARY` e o índice simples `empresa_id`,
sem `uq_unidades_empresa_sigla`.

> **Ressalva do MySQL (10.71):** ao criar o índice único, o MySQL descarta o
> índice implícito da FK `empresa_id`, e o índice único não pode ser removido
> sozinho (erro 1553, "needed in a foreign key constraint"). O downgrade
> desta migration já trata isso: recria o índice `empresa_id` antes de
> remover o único (validado num MySQL real, ida e volta duas vezes). Se mesmo
> assim aparecer o erro 1553, crie o índice à mão e repita o downgrade:
> ```bash
> mysql -u gestfila -p'<SENHA_MYSQL>' gestfila -e "CREATE INDEX empresa_id ON unidades (empresa_id);"
> flask db downgrade b3d6f8a1c4e7
> ```

### E.2. Voltar o código

```bash
git checkout --detach <COMMIT_ANTERIOR>
git log --oneline -1
sudo systemctl restart gestfila
sudo systemctl status gestfila --no-pager
sudo journalctl -u gestfila -n 50 --no-pager
```
**Esperado:** `git log` mostra `<COMMIT_ANTERIOR>`; serviço `active
(running)` sem erros.

Para voltar ao código novo depois (já corrigido): `git checkout master && git
pull --ff-only origin master`, e refazer B.5 e B.6.

### E.3. O que fica no banco depois do rollback (normalmente nada a fazer)

- **Siglas cadastradas no passo C:** continuam gravadas em `unidades.sigla`
  (a coluna existe desde o 10.22). O código antigo já as usa como prefixo —
  sem problema.
- **Locais atualizados pela prévia:** continuam com o prefixo novo (ex.:
  "[ACM] Guichê 1"). É texto livre e único — o código antigo exibe
  normalmente.

### E.4. Restaurar o backup (ÚLTIMO recurso)

Só se o banco tiver ficado inconsistente. **Restaurar o backup APAGA tudo o
que foi gravado depois dele** (senhas geradas, atendimentos, logs) — se o
sistema já voltou a ser usado, prefira E.1 + E.2 sem restaurar.

```bash
sudo systemctl stop gestfila
gunzip -c <ARQUIVO_BACKUP> | mysql -u gestfila -p'<SENHA_MYSQL>' gestfila
mysql -u gestfila -p'<SENHA_MYSQL>' gestfila -e "SELECT version_num FROM alembic_version;"
sudo systemctl start gestfila
sudo systemctl status gestfila --no-pager
```
**Esperado:** `alembic_version` = `b3d6f8a1c4e7` (estado do backup,
compatível com `<COMMIT_ANTERIOR>`); serviço `active (running)`. Faça E.2
(código anterior) antes de religar, se ainda não fez.
